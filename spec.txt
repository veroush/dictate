Technical Specification: Lock-Screen Voice-to-Webhook MacroThis specification details the native Android implementation for an app that intercepts hardware volume button presses to trigger a lock-screen voice transcription pipeline, sending the final text to a user-configured webhook.1. System Architecture & ComponentsThe application relies on three core components interacting via localized intents and system callbacks:[Hardware Vol+ Press] -> AccessibilityService -> Launches Activity
                                                      |
                                             SpeechRecognizer (STT)
                                                      |
[Hardware Vol+ Release] -> AccessibilityService -> Stops Activity -> OkHttp (Webhook)
Component BreakdownButtonInterceptorService (AccessibilityService): Runs continuously in the background. Intercepts global hardware key events (KEYCODE_VOLUME_UP) even when the device is locked.TranscriptionActivity (Activity): A lightweight UI component forced to display above the keyguard/lock screen. Manages the lifecycle of the speech recognition engine.WebhookClient: A background network utility (using OkHttp) responsible for executing the asynchronous POST request to the destination server.2. Component Detailed Design2.1 The Trigger: ButtonInterceptorServiceThis service must extend android.accessibilityservice.AccessibilityService.Configuration (res/xml/accessibility_service_config.xml):XML<accessibility-service xmlns:android="http://schemas.android.com/apk/res/android"
    android:accessibilityEventTypes="typeAllMask"
    android:accessibilityFeedbackType="feedbackGeneric"
    android:accessibilityFlags="flagRequestFilterKeyEvents"
    android:canRetrieveWindowContent="false" />
Key Event Logic:Override onKeyEvent(event: KeyEvent): Boolean.On ACTION_DOWN: If event.keyCode == KeyEvent.KEYCODE_VOLUME_UP, record the timestamp ($T_{start}$) and start a runnable handler with a 500ms delay. If the button is released before 500ms, cancel the runnable. If the runnable fires, trigger Long Press Execution.On ACTION_UP: If transcription is currently active and the time delta ($T_{end} - T_{start}$) is short (< 300ms), trigger Short Press Execution to stop transcription.Return Value: Return true for handled volume events to prevent the system from changing the media/ringer volume.2.2 The Interface: TranscriptionActivityThis activity acts as the visual overlay and orchestrator for the microphone.Lock Screen Bypass: Must be declared in the AndroidManifest.xml with specific flags:XML<activity 
    android:name=".TranscriptionActivity"
    android:showOnLockScreen="true"
    android:showWhenLocked="true"
    android:turnScreenOn="true"
    android:launchMode="singleInstance"
    android:theme="@style/Theme.TransparentOverLockScreen" />
Lifecycle Management:onCreate(): Invoke setShowWhenLocked(true) and setTurnScreenOn(true). Initialize the SpeechRecognizer.onStart(): Immediately start the SpeechRecognizer using RecognizerIntent.ACTION_RECOGNIZE_SPEECH.onDestroy(): Safely destroy the SpeechRecognizer instance to release the microphone hardware.2.3 The Voice Engine: SpeechRecognizerImplementation: Utilize native android.speech.SpeechRecognizer.Listener: Implement RecognitionListener.onPartialResults(bundle: Bundle): Extract SpeechRecognizer.RESULTS_RECOGNITION. Update a full-screen TextView with the real-time interim text so the user has visual confirmation.onResults(bundle: Bundle): Extract the final string array, pick the highest-confidence string (index 0), and pass it directly to the WebhookClient.2.4 The Outbound Pipeline: WebhookClientExecution: Use a standard OkHttpClient to execute an asynchronous POST call.Payload Structure:JSON{
  "timestamp": 1717701830,
  "text": "The transcribed text goes here."
}
Thread Safety: Network calls must be made on a background dispatcher (Dispatchers.IO if using Kotlin Coroutines) so they do not block the UI or main application thread during activity dismissal.3. Security & Permissions ChecklistBecause this application bypasses traditional Android sandbox constraints, the user must manually grant these permissions during initial setup:android.permission.RECORD_AUDIO: Required to access the microphone stream.android.permission.INTERNET: Required to communicate with the remote webhook endpoint.android.permission.BIND_ACCESSIBILITY_SERVICE: System-level permission required to intercept hardware keys globally.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS: Necessary to prevent Android's Doze mode from killing the background service wrapper.Warning on Implementation: Android's SpeechRecognizer sometimes fails to initialize seamlessly from a background service launch if the device is deeply asleep. If you experience initialization lag, you may need to acquire a temporary WakeLock inside the AccessibilityService right before starting the activity.
